# Presentation package — AtiSim CAT validation evidence base

Built to answer one question: **"How valid is the engine at predicting real aircraft
response in CAT encounters, and how do we know?"**

This is the **evidence base**, not the slides. Everything here traces to a run made in this
session or to a literature value already cited in the repository.

The `t1_*`, `target2-*`, `target3_*`, `target6_*`, `navion_*` and `sweep*` logs come from a
**parallel investigation pass** run over the same six targets. That pass was interrupted
before it reported, but its command output survived and is kept here because it
**independently corroborates** the primary numbers — `target2-lateral-modes-chain.log`
reproduces all eight mode figures to six decimal places, and `sweepB_inertias.log`
reproduces the inertia table exactly. Cross-checks by an independent run are worth more than
one run repeated. Logs from that pass that errored or came back empty were deleted rather
than kept.

Two findings in this package come only from that pass and are cited to it:
`CYp = CYr = 0` in the 747 lateral set (`known_issues.md` §14) and the existence of a
separate `WINGROVE_FIG4_CASES` alongside `PARKS_CASES` (`known_issues.md` §1).

## Provenance tags

The repository's own four-way vocabulary (`atisim/provenance.py`), carried through the
scorecard:

- **SOURCED** — read directly from a cited table.
- **DERIVED** — computed from SOURCED values by a stated exact relation.
- **CALIBRATED** — fitted so the model reproduces a SOURCED number.
- **DECLARED** — chosen; not derivable from any source held. Carries a sensitivity range.

## Method and integrity notes

**Which tree was tested.** The project warns that a worktree shares the main checkout's
virtualenv and can silently import the wrong `atisim`. Checked before every run in this
package — all resolved to the worktree:

```
C:\Users\mateusz\UROP\Claude_Flight_Sim\.claude\worktrees\cv-entry-project-e44ed6\atisim\__init__.py
```

**Nothing was modified to make a comparison look better.** No tolerance was loosened, no
test edited, no parameter adjusted. The investigation was read-only on all source and test
files; the only files written are this package and figures under `runs/cat/`.

**Where no run exists, cells are blank.** Five scorecard rows have blank
predicted/reference values. That is the correct representation: a blank means *no artifact
backs this*, and inventing a plausible number there would be the one project-breaking error.

**Three corrections to the task brief** are documented in `known_issues.md` §1, §3 and §4 —
two of them name the wrong aircraft, and one inverts the physics. They are corrected against
the repository rather than propagated.

**One deviation from the requested format:** the scorecard has a `quantity` column, so a
target spans several rows. A single row per target could not hold predicted/reference/error
for a target with eight measured quantities without inventing an aggregate — which ground
rule 1 forbids. Columns requested by the brief are all present.
